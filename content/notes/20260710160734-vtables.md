Vtables and using function pointers is generally how runtime polymorphism is defined. The trick is to embed a `vtable`, which is just a struct containing function pointers, in each instance.

```c
struct base {
  // Just to signal to others that this shouldn't be touched
  const struct base_vtable* _vtable;
  const char* data1;
  const int   data2;
  // ...
};

// Add your methods here
struct base_vtable {
  const char *(*talk)(void);
  const void *(*work)(void);
};

// Base function calls
static inline void *base_work(struct base *base)
{
  return base->_vtable->work();
}
```

And then to implement members, you have several options but they kind of involve the same idea: filling up the vtable and creating the struct. You can create helper methods to mask the vtable, or you can just leave it as is

```c
// in sub.c
static const void  work(void) { ... }
static const char* talk(void) { ... }
static const struct base_vtable* TABLE = { talk, work };

void sub_init(struct base* base)
{
  base->_vtable = TABLE;
  // ... more stuff ...
}
```

Then you would just use `base_talk(instance)`. You can also cast between subtypes. Of course, the vtable is a layer of indirection, which has to be considered if you are looking at performance. Compared to [Tagged Unions](@/notes/20260710145041-tagged_unions.md), this is trading speed for space.
