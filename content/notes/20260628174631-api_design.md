Aside from the basics (resource-oriented design) and the following methods

-   POST: create resource and return it
-   GET: return resource or resources
-   PATCH: replace parts of a resource and return it
-   PUT: completely replace resource and return it

It seems it is also common to have a \`list\` endpoint to get a bunch of resources of the particular. This endpoint can optionally have filtering if needed.

I think it most cases PATCH should be avoided, unless you are updating something trivial, like a user's settings or details of some item. That is, the updated values should not trigger a side effect. If it does trigger a side effect, it probably should belong in PUT.
