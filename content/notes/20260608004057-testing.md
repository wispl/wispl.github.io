## Test Driven Development {#test-driven-development}

Tests are really hard at least for me. In a broad sense, testing is the only way to ensure a program runs correctly. Although nowadays there are mathematical proofs as well. Although I really like the idea **TDD** (Test driven development), I have not actually used it at all. But I really should... TDD means tests are incorporated from the get go

1.  list requirements for some functionality or feature
2.  write tests matching those requirements, at this stage the tests should all fail
3.  write code which passes all of the tests (bad code is fine right now)
4.  refactor and improve the code while ensuring all tests keep passing

More tests is good (tests should be small). Repeat until program is finished.
