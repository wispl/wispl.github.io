## Tagged Unions {#tagged-unions}

We can use a union along with a struct member, likely an enum, to tell which type the instance is. A sample implementation could be something like the following

```C
struct stuff {
  enum stuff_type type;
  union {
    struct stuff_a a;
    struct stuff_b b;
    struct stuff_c c;
  } data;
}
```

This implementation is known as a **Tagged Union** or **unboxed**. Of course, the size of `data` would be the largest of the `Event` types. Then you would write the usual functions, but add in a switch case

```c
void stuff_do(struct stuff *s)
{
  switch (s->type) {
  case STUFF_A: // ...
  case STUFF_B: // ...
  case STUFF_C: // ...
  }
}

// Alternatively, you can use Visitor pattern, and dispatch accordinglg
struct stuff_visitor {
  void (*visit_a)(stuff_a* a);
  void (*visit_b)(stuff_b* b);
  void (*visit_c)(stuff_c* c);
}
```

It is worth noting that the equivalent of this in C++ is

```c++
using Stuff = variant<StuffA, StuffB, StuffC>;
std::visit(
  Overload {
      [](const StuffA& a) -> { ... }; },
      [](const StuffB& b) -> { ... }; },
      [](const StuffC& c) -> { ... }; },
  },
  stuff
);
```


## Tagged Pointers {#tagged-pointers}

This is very similar to Tagged Unions, except we use a pointer, which makes this **boxed**, because the pointers serves as a box for the actual data. There are several approaches to this

```c
// We store type information on the lowest three bits of the pointer
struct stuff {
  void* type_and_data;
}

// The above method only gives us 2^3 = 8 possible types. For more types we
// have to use a "fat pointer". The extra member allows us to have more types.
struct big_stuff {
  enum stuff_type type;
  void* data;
}
```

The main reason for tagged pointers is to save space, especially when one of the types have a really large size compared to the other types.


## Even More Types {#even-more-types}

Instead of fat pointers, another interesting technique is to use subtypes. Instead of stuffing all types into the three bits of a tagged pointer, you can stuff the additional types into the data. For example

```c
// Lets say we have three types: A, B, C
struct stuff {
  void* type_and_data;
}
// For each of the types, we have subtypes, let's consider type A only
struct stuff_a_base {
  union stuff_a_subtypes header; // Could be an enum too, if you want
  struct stuff_data data[];
}
// Derived type
struct stuff_a_sub_a {
  union stuff_a_subtypes header; // This must be first
  struct stuff_data data1;
  struct stuff_data data2;
}
```

Now once we see an instance of `stuff`, we check the pointer to see the type. If it is of type `A`, we then cast the pointer to `stuff_a_base` and then read the header (first field) to see the type. This ideally identifies the subtype (you can embed more information if you want, hence why it is a union).

After finding the subtype, you can cast to its derived type. If we find that the subtype is `sub_a`, we can cast to `stuff_a_sub_a` now and read the data. The header can be anything, as long as there is something identifiying the subtype somewhere.

Note that doing this on raw pointers will lead to Undefined Behavior (pointer provenance), so you will have to cast to `uintptr_t` first before manipulating bits. Manipulating bits of raw pointers always seems to lead to some weird shenanigans, it seems...
