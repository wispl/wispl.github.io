## Introduction {#introduction}

An example implementation of an event loop for sensors by emulating classes in C. It is obviously much easier and less boilerplate if you are using C++ instead. I think this method is fairly flexible and should be good enough, but there are probably better methods out there.


## Base Class {#base-class}

We start out with the base sensor class, which looks something like this

```c
typedef void* sensor_context;
// using void* for simplicity, you should define an actual packet struct
typedef void* packet;
struct sensor {
        void (*read)(sensor_context, packet);
        sensor_context context;
};
void init_sensor(sensor *s, *(*read)(sensor_context) callback, sensor_context ctx);
```

Every sensor must then fill out an instance of this struct to be used correctly. The `sensor_context` is passed to the callback function `read` when an event is received. You would use this to read values from the sensor and update or calculate what stuff you need. Here is a possible implementation

```c
bool barometer_init(sensor *s)
{
        // fancy initialization stuff...
        init_sensor(s, my_callback);
        // not so fancy post-initialization stuff...
}
```

The `sensor_context` is just a generic pointer and adds more flexibility, for example you can use it to assign UART or SPI handles or use it update data packets by adding these fields to a context object, and then using them via casting in the callback function;


## Event Dispatcher {#event-dispatcher}

I think the simplest way to use the event dispatcher is to use an `enum` for the event type and use it to index into an array of sensors. Something like this (me thinks)

```c
enum Event { BAROMETER_EVENT, IMU_EVENT, EVENTS_LENGTH };
sensor sensors[EVENTS_LENGTH];
struct packet packet = {0};

void init_sensors()
{
        barometer_init(&sensors[BAROMETER_EVENT]);
        imu_init(&sensors[IMU_EVENT]);
        // other stuff you want...
}

void handle_event(enum Event event)
{
        sensors[event].read(sensors[event].context, &packet);
}
```

Event handling can be done in a bunch of ways. In FreeRTOS, I have seen two main approaches

1.  Task per sensor, wake up via interrupt or just poll at a rate
2.  Event queue, interrupts add events to the queue

I lean towards 2, because there are less tasks which means less stack memory and less context switches. For this, you can just use the builtin FreeRTOS queue and then have a task which takes and blocks on that queue. For 1, you would just create a task for each sensors and run them.
