## Introduction {#introduction}

Server Side Rendering (SSR) is when HTML is rendered on the server and then sent to the client. This is different for Single Page App (SPA), where all HTML and Javascript is sent to the client on first load and then executed throughout the life cycle of the app. Now consider an app which queries the backend server for data, the difference between SSR and SPA are shown below


## SPA {#spa}

1.  First load, client downloads frontend files served as bundle
2.  Client uses the app, frontend uses Javascript to query backend for data
3.  Backend might query databases for data and session, and then sends it to frontend
4.  Frontend receives data and displays it to the user


## SSR {#ssr}

1.  First load, server sends generated HTML to client
2.  Client uses the app, server queries databases for data and session
3.  Server generates HTML from data and sends it to client
4.  Client receives and renders the HTML


## Differences {#differences}

Under SPA, Javascript is required while under SSR it is optional. SSR shifts more of the work towards the server. Unfortunately I have not found too much benchmarks on just how much work this makes. Things also get a bit tricky since SSR (at least Sveltekit) can pre-render and cache pages so that the HTML generation is less work.

From a latency standpoint, SSR should be better since there is less roundtrips. There are other benefits like faster initial page load and better SEO but they are rather circumstantial and really depends on your environment.

Sveltekit makes SSR really easy to do compared to React, which kind of makes SSR more viable because the complexity aspect is gone. Of course the issue is now scalability and much more load will it add to the server. For example consider

-   SPA: server acts as backend and can serve the SPA (or you can use CDN)
-   SSR: server acts as backend (can use sveltekit or an actual backend) and must now also generate HTML

Under SSR, the workload of each server is increased. Right now I am not entirely convinced that the extra server workload is justified. Since the projects I work on act as apps, SPA is a better fit.
