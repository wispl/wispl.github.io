See <https://testing-library.com/>. I believe this is a good solution for testing individual components to make sure they look right. The library has broad support for many frameworks, and in short you can "mock" backend responses and then test if your components render correctly. Here is the library's example using svelte

```js
import {render, screen} from "@testing-library/svelte";
import {userEvent} from "@testing-library/user-event";
import {describe, it} from "node:test";

import Calendar from './Calendar.svelte'

describe("My component", () => {
  it('renders correctly with props', () => {
    render(Calendar, { calendarId: 232 });

    const calendar = screen.getByRole('calendar', { id: 232 });
    expect(button).toBeInTheDocument()
    expect(greeting).not.toBeInTheDocument()
  })
})
```

Component testing should be sufficient, but if there is a time a test using playwright might also be beneficial to test, for example, login flows or work flows. But that is a bit more work. For playwright, you can actually record actions using your browser and then use that for testing (the recorded actions are replayed in tests). This is pretty good as a test-generator.

-   <https://playwright.dev/docs/codegen>
