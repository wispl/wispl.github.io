## Introduction {#introduction}

Useful for a lot of things. Currently using this for an event loop. In theory, an event loop is simple, you add events to a queue, than have the loop continuously consume and act on events in the queue. Implementation-wise, there are several ways you can implement an event loop. The three main parts of an event loop are

1.  event queue: stores events to be consumed
2.  event handlers: a callback usually, basically how to handler a specific event
3.  event dispatchers: basically something which assigns events to event handlers

For simplification, the event queue is handled by something else, which I think is usually the case, in GUI applications you would do some form of subscribe or notifier model, while in [Embedded](@/notes/20260321032721-embedded.md) (event loop for querying sensors), you would use interrupts to add events to the event queue.


## Switch It Up {#switch-it-up}

The more interesting bits is how to implement the event handlers and dispatchers, as there are several ways. The simplest way is to define functions and then use a switch-case statement for the handler and dispatcher

```C
// Can have arguments if you want
void handle_good_event() { ... }
void handle_bad_event() { ... }

enum EventType { GOOD_EVENT, BAD_EVENT };

void dispatch_events(enum EventType type)
{
        switch (type) {
        case GOOD_EVENT: handle_good_event();
        case BAD_EVENT: handle_bad_event();
        }
}

void event_loop()
{
        while (true) {
                enum EventType curr = event_queue.take();
                if (curr) dispatch_event(curr);
        }
}
```

## In Case You Like Callbacks {#in-case-you-like-callbacks}

You can instead use function pointers for the handles, which will make the code look similar to something like this

```C
// Can have arguments if you want
void handle_good_event() { ... }
void handle_bad_event() { ... }

typedef void *(*EventHandler)(void *);
enum EventType { GOOD_EVENT, BAD_EVENT, EVENTS_LENGTH };
EventHandler handlers[EVENTS_LENGTH];

void init_events()
{
        handlers[GOOD_EVENT] = &handle_good_event;
        handlers[BAD_EVENT] = &handle_bad_event;
}

void event_loop()
{
        while (true) {
                enum EventType curr = event_queue.take();
                handlers[curr]();
        }
}
```

It is about the same either way, but function pointers give a bit more flexibility, though there is probably a super tiny cost due to an extra pointer indirection. But this flexibility makes a lot of patterns possible (I think). For example, see [Sensor Loop](@/notes/20260628004304-sensor_loop.md).
